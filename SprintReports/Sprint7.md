Sprint Report B– Sprint 7
Scrum Master: Caleb Blevins
Sprint Dates: 3/29/2026- 4/3/2026
GitHub Repo: https://github.com/SamMccorke1/SE2-Project—Casino.git
 
Sprint Goal (Descriptive Statement)
The goal of this sprint was to finalize core backend functionality by integrating wallet logic with game systems, continue development across game features, and improve frontend structure while ensuring testing and system reliability.
 
PBIs Chosen for the Sprint
We selected PBIs based on priority of core system functionality and dependencies between features. The wallet system and game logic were prioritized because they are required for full gameplay functionality.
Selected PBIs
●	Wallet system implementation and testing

●	Integration of wallet with game logic

●	Game logic testing and bug fixing

●	Frontend page development

●	Character design implementation

Decision Process
PBIs were chosen based on:
●	System dependencies (wallet needed before full gameplay testing)

●	Team velocity from previous sprint

●	Estimated complexity (story points)

●	Priority of getting a playable system working

 
Sprint Planning Activity Summary
During sprint planning, we:
●	Reviewed backlog and prioritized critical system components

●	Assigned tasks based on strengths (backend, frontend, design)

●	Broke PBIs into actionable tasks

●	Estimated time based on previous sprint performance

 
Tasks Planned
Task 1
●	Owner: Me

●	Title: Wallet Logic Implementation

●	Description: Build and test wallet functionality (balance updates, transactions)

●	Status: Complete

●	Challenges: Ensuring accuracy across all transaction scenarios

●	Lessons Learned: Need to test edge cases early

●	Planned Time: 6 hrs

●	Actual Time: 8 hrs

 
Task 2
●	Owner: Me

●	Title: Wallet + Game Logic Integration

●	Description: Connect wallet system with gameplay mechanics

●	Status: Complete

●	Challenges: Integration inconsistencies across different game flows

●	Lessons Learned: Integration requires more time than isolated development

●	Planned Time: 5 hrs

●	Actual Time: 7 hrs

 
Task 3
●	Owner: Reo

●	Title: Game Logic Testing

●	Description: Test gameplay functionality and identify bugs

●	Status: Complete

●	Challenges: Edge cases in game outcomes

●	Lessons Learned: Testing is critical before scaling features

●	Planned Time: 5 hrs

●	Actual Time: 6 hrs

 
Task 4
●	Owner: Lucas

●	Title: Page Development

●	Description: Build and refine frontend pages

●	Status: Complete

●	Challenges: Connecting frontend with backend logic

●	Lessons Learned: UI depends heavily on backend stability

●	Planned Time: 3 hrs

●	Actual Time: 4 hrs

 
Task 5
●	Owner: Matthew

●	Title: Character Design

●	Description: Create casino character visuals

●	Status: Complete

●	Challenges: Matching theme and consistency

●	Lessons Learned: Design impacts user engagement

●	Planned Time: 4 hrs

●	Actual Time: 5 hrs

 
Task 6
●	Owner: Sam

●	Title: Poker Completion & Blackjack Fixes

●	Description: Finalize poker and resolve blackjack issues

●	Status: Complete

●	Challenges: Debugging logic inconsistencies

●	Lessons Learned: Game logic requires iterative testing

●	Planned Time: 6 hrs

●	Actual Time: 7 hrs

 
Roadblocks
We ran into a major roadblock with GitHub merging conflicts, specifically involving test integration and build artifacts. This slowed progress temporarily, but we worked through the issues and eventually got the kinks sorted out.
 
Sprint Review
Was the sprint goal achieved?
Yes — we successfully completed the sprint goal.
Why
●	Core systems (wallet + game logic) were integrated

●	Game functionality improved

●	Frontend and design progressed

Acceptance Testing (Product Owner Feedback)
●	System functionality is improving

●	Integration is working but still needs continued testing

Adjustments Planned (Product)
●	Expand testing across all game systems

●	Improve gameplay flow and stability

Revised Definition of Done
●	Feature must be functional

●	Tested before completion

●	Integrated into the overall system

Sprint Review Summary
Overall, the sprint was successful. Even though we hit a roadblock with GitHub merging, we still finished the sprint goal and made strong progress across backend, frontend, and game systems.
 
Sprint Retrospective
What went well
●	Strong team collaboration

●	Major system integration was completed

●	Everyone contributed in their assigned area

What didn’t go well
●	GitHub merge conflicts slowed us down

●	Some integration work took longer than expected

Adjustments Planned (Process)
●	Improve GitHub workflow and branch management

●	Check integration earlier in the sprint

●	Keep testing more consistent throughout development

Sprint Retrospective Summary
The team worked well together and adapted once we hit technical issues. Going forward, we need to tighten our GitHub process and integrate more often to avoid unnecessary slowdowns.
 
Team Velocity
Team velocity remained strong this sprint since all major planned tasks were completed, even with time lost to technical issues involving GitHub merging.
 
Backlog Grooming Activity Summary
●	Reprioritized testing-related PBIs

●	Added more integration-focused work

●	Removed completed wallet-related tasks

●	Shifted more attention toward full gameplay testing

Definition of Ready (DoR)
A backlog item is considered ready when:
●	it is clearly defined

●	dependencies are known

●	acceptance criteria are included

●	the team understands the task well enough to begin work
